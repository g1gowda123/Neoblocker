## 2024-06-13 - Extension Background Script Error Information Leakage and Lack of Validation
**Vulnerability:** The extension `background.ts` handler was exposing internal exception details (`String(err)`) to content scripts across the extension message passing boundary, potentially leading to information disclosure. Further, parameters such as `videoId` and `text` were not validated or bounds-checked, allowing for arbitrary inputs (length unbounded or arbitrary strings) that could lead to DoS, memory exhaustion, SSRF or request smuggling down the line.
**Learning:** Browser extension message passing must be treated as crossing a security boundary. Inputs received from content scripts running in the context of potentially hostile web pages must be strictly validated. Errors propagated back over message passing should be generic to prevent leaking stack traces or internal implementation details.
**Prevention:** Always validate and bound inputs in background service workers using explicit typing, regex validation, and length constraints. Return generic, safe error messages to content scripts to prevent internal information leakage.

## 2024-06-13 - URL Verification SSRF via Hostname Resolution Bypass
**Vulnerability:** The `/verify` endpoint fetched user-provided URLs using `AsyncWebCrawler` without sufficient hostname validation. While the endpoint validated the URL scheme, it lacked robust hostname checks, relying solely on basic string matching. This permitted Server-Side Request Forgery (SSRF) and Server-Side Request Smuggling (SSRS), where attackers could hit internal networks by using obscure IP formatting (like `127.1`) or by setting up public DNS records that resolved to internal IPs (like `localtest.me` pointing to `127.0.0.1`).
**Learning:** Basic string matching against hostnames is insufficient for SSRF protection because DNS and IP representations are highly flexible. An attacker can easily bypass string filters using hex, octal, shortened IPs, or custom DNS rebinding.
**Prevention:** To effectively prevent SSRF, always resolve the provided hostname to its underlying IP address using `socket.gethostbyname` (or `asyncio.get_running_loop().getaddrinfo()` in async contexts) and explicitly verify that the resolved IP does not fall within private, loopback, multicast, or link-local ranges using Python's `ipaddress` module before making the outward request. Note that while this mitigates standard SSRF, complete protection against DNS rebinding (TOCTOU) requires enforcing the resolved IP directly in the crawler/client.
