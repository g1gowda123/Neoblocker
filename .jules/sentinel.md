## 2024-07-27 - [Parameter Injection / Application-Layer DoS via API Key]
**Vulnerability:** The application extracted an API key from raw HTML (`html.match(/"INNERTUBE_API_KEY"\s*:\s*"([^"]+)"/)`) and directly appended it into an outgoing `fetch` URL query parameter (`?key=${apiKey}`) without length validation or URL encoding. Since the HTML was parsed from an external untrusted source (a YouTube page, where an attacker could theoretically control metadata or descriptions to inject fake tokens), this allowed for Parameter Injection (breaking out of the `key=` parameter to inject new URL structure) and Application-Layer DoS (by supplying excessively long strings leading to memory exhaustion or huge outbound payloads).
**Learning:** Even when extracting seemingly structured or internal keys from external HTML responses (like InnerTube tokens embedded in YouTube pages), they must be treated as untrusted user input if they originated from a system where users can influence content (like titles/descriptions).
**Prevention:** Always strictly validate the length of extracted tokens against expected bounds (e.g., `< 100` chars for an API key, `< 2000` chars for a continuation token) and apply `encodeURIComponent()` to the token before interpolating it into a URL to prevent parameter breakouts.
