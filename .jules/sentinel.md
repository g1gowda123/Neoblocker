## 2024-06-13 - Extension Background Script Error Information Leakage and Lack of Validation
**Vulnerability:** The extension `background.ts` handler was exposing internal exception details (`String(err)`) to content scripts across the extension message passing boundary, potentially leading to information disclosure. Further, parameters such as `videoId` and `text` were not validated or bounds-checked, allowing for arbitrary inputs (length unbounded or arbitrary strings) that could lead to DoS, memory exhaustion, SSRF or request smuggling down the line.
**Learning:** Browser extension message passing must be treated as crossing a security boundary. Inputs received from content scripts running in the context of potentially hostile web pages must be strictly validated. Errors propagated back over message passing should be generic to prevent leaking stack traces or internal implementation details.
**Prevention:** Always validate and bound inputs in background service workers using explicit typing, regex validation, and length constraints. Return generic, safe error messages to content scripts to prevent internal information leakage.
## 2024-06-28 - Log Injection Fix in Verification API
**Vulnerability:** User-controlled input (`source_url`) and external data (`response.text`) were being printed directly to stdout using `print()` without sanitization. This allowed attackers to inject fake log entries by including newline (`\n`) or carriage return (`\r`) characters in the input.
**Learning:** Standard print statements and standard Python `logging` do not automatically escape newlines in log messages. When user input containing newlines is logged, it can create forged log entries that confuse administrators or mask malicious activity (CWE-117).
**Prevention:** Always use a properly configured logging framework instead of raw `print` statements, and explicitly sanitize any user-controlled or external strings by replacing `\n` and `\r` with their escaped representations (`\\n` and `\\r`) before logging them.

## 2024-05-27 - [Async SSRF Protection]
**Vulnerability:** Blocking synchronous DNS lookup (`socket.gethostbyname`) inside an asynchronous FastAPI endpoint, potentially causing the event loop to block. Insufficient IP checks for SSRF protection.
**Learning:** In asynchronous Python apps, using synchronous functions like `socket.gethostbyname()` can block the event loop and degrade performance. `asyncio.get_running_loop().getaddrinfo()` must be used instead. Additionally, when mitigating SSRF, all possible resolved IPs from `getaddrinfo` must be checked, and filters should include `is_multicast` and `is_unspecified` (0.0.0.0 or ::) alongside private/loopback/link-local ranges.
**Prevention:** Always use non-blocking functions for DNS resolution in async code. Iterate through all resolved IPs and use `ipaddress` to strictly block private, loopback, link-local, multicast, and unspecified addresses.
## 2024-06-29 - [TOCTOU DNS Rebinding SSRF Fix in Chromium Crawler]
**Vulnerability:** The FastAPI verification endpoint mitigated SSRF by checking `getaddrinfo` on the provided hostname and blocking private/loopback IPs. However, it then passed the original URL to `AsyncWebCrawler` (a playwright/chromium wrapper). This creates a Time-of-Check to Time-of-Use (TOCTOU) DNS rebinding vulnerability, as Chromium performs its own DNS resolution, allowing an attacker to rapidly change the DNS record to point to an internal IP after the check passed but before the crawl occurs.
**Learning:** Simply replacing the hostname with the raw IP address in an HTTPS URL (e.g., `https://1.1.1.1/`) breaks Server Name Indication (SNI) during the TLS handshake, causing the crawl to fail on almost all modern websites, even if the `Host` HTTP header is injected.
**Prevention:** To mitigate DNS rebinding in Chromium-based libraries without breaking SNI, use the `--host-resolver-rules=MAP <hostname> <validated_ip>` command-line flag (e.g., via `BrowserConfig`'s `extra_args` in `crawl4ai`). This forces the browser to use the safely validated IP address at the network layer while preserving the original hostname for the TLS SNI and HTTP Host headers.
